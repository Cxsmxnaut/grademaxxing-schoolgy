# StudentVUE modern API contract map

Grademaxxing exposes a read-only, same-origin JSON API under `/api/studentvue`. A user first signs in through `POST /api/session`; credentials are used for the StudentVUE form login and are not returned to the browser or stored in local storage. Subsequent calls use the opaque `grademaxxing_session` cookie.

`GET /api/studentvue/capabilities` is the machine-readable inventory. All resource routes reject missing or upstream-expired sessions with HTTP 401, invalid parameters with HTTP 400, unknown resources with HTTP 404, upstream StudentVUE failures with HTTP 502, and upstream timeouts with HTTP 504. A detected upstream expiry also deletes the local session and cookie so clients cannot remain stuck in a false signed-in state.

## Gradebook fidelity

The modern gradebook is not one request. `PXP.GBFocusData.GradingPeriods` is the canonical ordered period catalog. The optional `reportPeriod` parameter is its zero-based index, matching the legacy SOAP contract. Selecting a non-current period loads the first-party `Gradebook_SchoolClasses` control with that period's opaque identifiers; the returned class markup then supplies the period-specific class focus parameters. The XML response reports the real period names and selected index.

StudentVUE stores both the selected period and focused class in its server session, so complete gradebook reads are serialized per signed-in session. Within each class, independent structured requests are made in parallel. `GetClassData` is authoritative for percentage, calculated/manual mark, weighting mode, categories, category points, missing marks, drop-score rules, rounding rules, score-type metadata, and the complete set of graded assignment IDs. When a graded ID is absent from the visible course-content feed, Grademaxxing requests only that ID's `Gradebook_AssignmentDetails` fragment and recovers its real name, category, dates, score, points, notes, and description. This replaces SOAP's complete assignment list without returning to a slow request for every visible assignment.

## Compatibility limits

The PXP2 portal is configured per district. An empty array means the district exposed the feature but has no records for the signed-in student. HTTP 502 means the expected first-party contract was absent or changed. Write operations—sending messages, submitting assignments, reporting absences, and editing profile data—are intentionally excluded.
